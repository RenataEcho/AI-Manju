# AI 漫剧 V2.3.1｜节点分支与创作版本增强规则

## 一、版本定位
在 V2.3 方案 B 小说三栏工作台上增量实现 AI 对话节点分叉。保留小说创作、全书/章节两级大纲、简单/专业模式、AI Mock 候选确认、章节版本和原有漫剧制作链路。此版本不接入真实模型。

## 二、数据关系
- `Novel`：小说作品主体；正式章节正文、大纲、世界观、人物等跨分支共享。
- `Branch`：对话分支，含 `id/title/parentId/sourceMessageId/inheritedCount/messages/summary/archived`。
- `Message`：对话消息，含稳定 `id/role/content`，可作为分叉节点。
- `Candidate`：每个分支独立保留的待确认生成结果，含 `branchId/doc/baseHash/text/type`。
- `Version`：正式文档的内容快照，与分支对话分离。
- 本地演示中分支存储在小说工作台独立的 localStorage 数据结构；不作为云端并发方案。

## 三、交互规则
| 位置 | 功能 | 规则 |
|---|---|---|
| 右侧 AI 消息 | 从此分支 | 点击任意消息上的“从此分支”，继承该消息及之前的对话快照，记录来源分支与节点；后续父分支消息不自动同步。 |
| 右侧 AI 顶部 | 从最新节点分支 | 继承当前分支截至最新消息的历史；若为空则创建空对话分支。 |
| 右侧 AI 顶部 | 切换分支 | 仅切换 AI 会话，不切换小说正文、设定、大纲和章节版本。 |
| 分支管理 | 列表 | 展示名称、摘要、消息数、来源分支、继承消息数和子分支数。 |
| 分支管理 | 搜索、改名 | 按名称/摘要搜索；改名不改变来源关系。 |
| 分支管理 | 归档与恢复 | 归档从活跃分支下拉中移除，历史保留；可恢复。主线不可归档。 |
| 分支管理 | 删除 | 二次确认；存在子分支时禁止删除；已应用的正文不删除。 |
| AI 生成 | 候选稿 | 生成候选绑定当前分支和目标文档，并记录目标文档生成时内容指纹。 |
| AI 应用 | 冲突校验 | 应用前重新比较目标文档指纹；不同则阻止直接应用，提示重新生成；相同则创建应用前快照，再写入正式文档。 |
| AI 上下文 | 查看引用 | 显示当前作品、文档、大纲、人物、世界观、分支摘要、来源节点及继承消息数；Mock 不代表真实模型 Token 计数。 |

## 四、验收清单
- [ ] 主线已有两轮对话，从第一轮 AI 消息分叉，新分支仅继承此前消息。
- [ ] 创建子分支后，主线追加消息，子分支消息不变化。
- [ ] 子分支修改对话，切换回主线时对话相互独立。
- [ ] 切换分支时，当前章节正式正文不变化。
- [ ] A/B 分支分别生成候选，切换后候选不串线。
- [ ] 候选生成后手动修改目标章节，再应用时触发版本冲突保护。
- [ ] 未修改目标章节时应用候选，自动保存应用前版本。
- [ ] 归档分支从活动列表移除，恢复后可重新进入。
- [ ] 有子分支的父分支不能删除，主线不能删除。
- [ ] V2.2.2 的小说/漫剧入口及五阶段生产流程不回退。

## 五、当前边界与后续
当前为可交互 Mock，支持浏览器本地持久化、分支消息快照、候选隔离及基础冲突保护；尚未实现真实 AI 推理、Token 预算、服务端摘要压缩、跨设备同步、多用户并发版本合并。上述验收清单需浏览器实测，不能以 JS 静态语法通过替代。
